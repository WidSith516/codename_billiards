# 球种与库边加速 · 参数调节说明

> 本文说明**现在可以调什么、在哪里调、改了会怎样**。
> 所有数值都在关卡 JSON 里，**改完即生效，不需要重新编译**。

---

## 1. 一句话现状

| 能力 | 状态 |
|---|---|
| 每种球有独立的 **质量 / 摩擦 / 弹性 / 库边增益 / 库边加速次数上限** | ✅ 已实现，全部数据驱动 |
| 库边加速**按次数上限**（每球独立计数） | ✅ 已实现 |

## 2. 在哪里调

在关卡 JSON 里加一个 `physics.types` 块。**关卡内的值会覆盖代码默认值**：

```json
"physics": {
  "types": {
    "cue":    { "mass": 1.0, "frictionDecel": -1,  "wallGain": 120, "maxWallBoosts": 3 },
    "object": { "mass": 1.0, "frictionDecel": -1,  "wallGain": 0,   "maxWallBoosts": 0 },
    "heavy":  { "mass": 3.0, "frictionDecel": 900, "wallGain": 0,   "maxWallBoosts": 0 },
    "bomb":   { "mass": 1.0, "frictionDecel": -1,  "wallGain": 0,   "maxWallBoosts": 0 },
    "anchor": { "mass": 1.0, "frictionDecel": -1,  "wallGain": 0,   "maxWallBoosts": 0 }
  }
}
```

球种名写进球的 `"type"` 字段即可：`"cue"` / `"object"` / `"heavy"` / `"bomb"` / `"anchor"`。
**`heavy` / `bomb` / `anchor` 以前只是无效字符串，现在是真正独立的类型。**

---

## 3. 每个字段是什么意思

| 字段 | 含义 | 默认 | 备注 |
|---|---|---|---|
| `mass` | 相对质量 | 1.0 | 越重，被撞后速度越小。实测：质量 3 的球被同一杆撞后速度只有普通球的 **0.54 倍** |
| `frictionDecel` | 滚动减速度 px/s² | 640 | 越大停得越快、滚得越近 |
| `restitution` | 球球碰撞弹性 | 0.955 | 越大撞后越快 |
| `wallGain` | **每次撞库加多少速度** px/s | 白球 120 / 其他 0 | 这就是「撞墙加速」的强度 |
| `maxWallBoosts` | **最多撞库加速几次** | 白球不限 / 其他 0 | `0` = 完全不加速；**负数 = 不限次数** |
| `collisionBoost` | 碰撞增能倍率 | 1.0 | **1.0 = 不增能**（见 §4） |

### 特殊值约定（重要）

- **`-1` 是「继承」哨兵**：`frictionDecel: -1` / `restitution: -1` / `wallGain: -1`
  表示「用代码里的锁定默认值」，不是字面上的 -1。
  这样做是为了让**出厂默认行为与之前逐位相同**，从而不破坏已通过验证的关卡。
- **`maxWallBoosts: -1`** 表示**不限次数**。

---

## 4. ⚠️ 「碰撞增能」默认关闭，以及为什么

你选择了「碰到球就被加速」。这个机制**已经接好了**，字段是 `collisionBoost`：

- `1.0`（默认）= 正常台球碰撞，能量守恒。
- `1.2` = 该类型的球在碰撞中获得的**速度再乘 1.2**，即凭空多出能量。

**为什么默认是 1.0：**

本项目现行的 4 个关卡，其「可通关角度窗口」（±2.42°～2.73°）是**在能量守恒的物理下测量的**
（见 `godot/LEVELS.md`）。一旦开启碰撞增能，球会比验证时跑得更远、撞得更多，
**这些窗口可能整体失效，关卡可能变得无解或变得过易**。

所以我把机制做成**可调但默认关闭**，并且**必须重新验证**才能开启：

```powershell
# 开启后必须重跑这一条，确认关卡仍然可解
powershell -NoProfile -ExecutionPolicy Bypass -File tools\author\run_author.ps1 -Command verify
```

**需要你决定**：是否要我**实测**开启后的影响？如果要，我需要知道你想要的强度
（例如只让 `heavy` 增能 1.15，还是全体 1.2），以及**接受关卡容差窗口发生变化**。

## 5. 现在的默认行为（与改造前逐位一致）

| 球种 | 质量 | 摩擦 | 弹性 | 库边增益 | 加速上限 |
|---|---|---|---|---|---|
| `cue` 白球 | 1.0 | 640 | 0.92 | **120** | **不限** |
| `object` 普通球 | 1.0 | 640 | 0.92 | 0 | 0 |
| `heavy` 重球 | **3.0** | **900** | 0.92 | 0 | 0 |
| `bomb` 炸弹球 | 1.0 | 640 | 0.92 | 0 | 0 |
| `anchor` 锚定球 | 1.0 | 640 | 0.92 | 0 | 0 |

> 白球默认**不限加速次数**（保持与验证时一致）。想改成有上限，把 `cue.maxWallBoosts`
> 设成 3 之类的正整数即可——但**同样要重新验证关卡**，因为白球的能量预算会变。

## 6. 调试面板

- **默认隐藏**。左侧面板只保留：击球状态、力度、**回溯预算**、操作说明。
- 按 **`F1`** 显示：采样点数、回溯段数、折返/回正计数、**撞库加速剩余次数**、待碰撞预告。
- 之所以保留「回溯预算」和操作说明：这两项**是规则本身**，藏起来新手会不知道怎么玩。
