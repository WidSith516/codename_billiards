# 《REWIND：一杆清台》游戏策划案

> 版本：V1.0｜2026-10-11｜8h Game Jam｜网页端单人机制原型  
> 状态：核心规则已在试玩原型中实现；玩法深度和平衡尚待实测

## 1. 一句话概念

**玩家只能击球一次，却可以不断让白球沿它实际走过的完整历史反向运动，在变化中的球桌上制造新的碰撞，直到打进全部目标球。**

这不是标准八球规则，也不是简单的 Ctrl+Z 撤销。它的核心是：**历史轨迹可回溯，但其他物体的状态不会随之复原。**

### 设计目标

1. 一条主要能力、少量物理规则，形成可以反复利用的系统交互。
2. 玩家能准确预测白球回溯会经过哪里，再利用其他球的当前站位制造结果。
3. 让首次击球、回溯时机、回溯距离、释放时机都成为有意义的决策。
4. 8 小时内能完成并验证核心乐趣，不依赖剧情、美术产量或多关卡。

## 2. 游戏概况与胜负

| 项目 | 规则 |
|---|---|
| 类型 | 俯视角单人台球／物理系统实验 |
| 平台 | 网页端，支持鼠标和触屏 |
| 场地 | 单张六袋球桌 |
| 球体 | 1 颗白球、10 颗目标球 |
| 核心目标 | 让全部 10 颗目标球入袋 |
| 击球次数 | **整个回合只允许一次**，不是每次回溯后再给一杆 |
| 回溯对象 | **仅白球** |
| 回溯次数 | 暂不限制次数，也不设置能量消耗 |
| 目标球进袋 | 永久计分、移出物理世界，回溯不会使其复原 |
| 白球进袋 | 不立即失败；可以通过回溯从球袋中返回 |
| 胜利 | 10 颗目标球全部进袋，显示清台结果 |
| 失败 | 原型阶段不设置时间上限、生命值或失败惩罚，可随时重开 |

不使用标准台球的犯规、指定球、轮流击球、黑八优先级等规则。这里的台球是一套容易理解的物理交互系统。

## 3. 操作与核心循环

### 操作

- **首次击球：** 按住白球向后拖动，决定方向与力度，松开击出。
- **按住 R / 按住网页按钮：** 白球回溯。
- **松开 R / 按钮：** 立即结束回溯，白球保留当前逆向速度，转入正常物理运动。
- **重新开局：** 重置整张球桌、全部历史、得分与唯一一杆的使用状态。

### 一局的核心循环

1. **制造历史：** 用唯一的一杆打散球群，形成初始运动轨迹。
2. **观察现在：** 其他球继续运动、碰撞、反弹、入袋，状态逐渐不同于白球的历史世界。
3. **回溯白球：** 沿既有路线返回，并撞击当前位于路径上的目标球。
4. **释放白球：** 在选择的时刻恢复正常物理运动，产生新的路径和碰撞。
5. **累计成果：** 目标球进袋永久保留，不断减少未完成目标，直到清台。

## 4. 时间回溯：必须严格遵守的规则

### 4.1 历史记录的是实际运动过程

设白球一次正向运动为 **A→B**；玩家在 B 开始倒流，到中间点 C 松手；白球以与 A→B 路过 C 时相反的速度方向继续运动至 D。

这次实际经过的路径依次是：

```text
A → B → C → D
    ↑   ↑
    |   在 C 松开回溯，继续实际运动到 D
    从 B 开始逆向返回 C
```

**历史必须追加保存为 A→B→C→D，而不是删除 B 之后的旧历史，也不是只留下 A→C→D。**

因此下一次回溯的次序为 **D→C→B→A**。即使某些空间位置被重复经过，它们在历史中也是不同时间的独立记录。

### 4.2 实现语义：冻结读取、追加记录

白球保存按时间顺序排列的历史状态序列：

\[
H=[s_0,s_1,\ldots,s_n],\quad s_i=(x_i,y_i,v_{x,i},v_{y,i})
\]

每次开始回溯时，对当时已经存在的历史创建一份**只读回放快照**，游标逐帧向前面的历史移动。

与此同时，白球在回溯期间每一次实际位移，仍然向主历史序列的尾部追加记录。这样不会出现“刚记录的倒退帧又立刻被自身倒流读取”的死循环。

松开 R 后，回放快照结束；主历史保留之前的所有运动和刚刚发生的倒退运动，并继续追加新运动。再次按 R 时，重新以当前完整历史创建快照。

原型暂不压缩或裁剪白球历史；正式版本需检查长时间游玩的内存占用，但不得悄悄删除玩家被承诺可以回溯的路径。

### 4.3 回溯时的位置与速度

- 回溯白球的位置由历史快照**强制决定**，而不是通过给速度取负后重新模拟全部物理。
- 当前世界中的其他球不能偏转或阻止回溯白球的历史轨迹。
- 回溯瞬间的速度按相邻两次历史位置的反向位移求得；在同一轨迹点，它与当初正向经过该点时的速度方向相反。
- 在任意 C 点松开 R，白球保留回溯瞬间的逆向速度，从 C 开始执行正常碰撞、摩擦、反弹。
- 回溯到所读取历史的起点时自动停止，速度归零；但本次回溯经过的路线仍已追加到主历史中。

### 4.4 回溯碰撞是单向作用

回溯白球碰到正常目标球时：

1. 白球必须继续沿已记录的历史轨迹运动，不因撞击而偏转。
2. 目标球被推出重叠区域，并根据接触方向与相对速度获得冲量。
3. 目标球随后继续执行正常物理。
4. 目标球受到的位移、动量和入袋结果**不会**因白球继续倒流而撤销。

因此回溯碰撞不要求机械能或总动量守恒。这是刻意定义的**游戏规则**，并非真实的反向物理模拟。

## 5. 正常物理与球桌

### 5.1 基础物理

- 所有球采用相同的基本半径和质量。
- 正常球—球碰撞使用近似弹性碰撞，并处理相互重叠。
- 球体持续受到滚动阻力，逐渐减速至静止。
- 库边使运动方向反射；入袋优先于库边反弹判断。
- 球体入袋后退出正常碰撞系统；白球可回溯救回，目标球不可恢复。

### 5.2 白球撞库动量 ×1.5

**仅白球在正常物理运动中撞击库边时**获得增益。设撞库前动量为 \(\mathbf p\)，库边法向单位向量为 \(\mathbf n\)，撞库后：

\[
\mathbf p'=1.5\bigl(\mathbf p-2(\mathbf p\cdot\mathbf n)\mathbf n\bigr)
\]

由于白球质量不变，等价于：反射运动方向后，**速度向量整体乘以 1.5**，不只是法向分量增加。

- 同一物理帧即使同时接触两条库边，也只施加一次 ×1.5。
- 彩球继续使用普通反弹系数，当前原型为 0.85。
- 回溯过程中经过历史上的撞库位置，不重新触发 ×1.5；原轨迹中已经包含了当时的反弹运动。
- 松开回溯后，白球重新进入正常物理，从此时开始的实际撞库可以再获得 ×1.5。

这项规则的设计作用是：**仅有一杆初始能量输入，但玩家能通过库边补充运动能力，避免白球很快永久停滞。**

需测试多次撞库是否会导致速度无限增长、碰撞穿透或操作失控。若出现问题，应先改善高速碰撞稳定性，再讨论是否需要速度上限或调整倍率。

## 6. 玩家决策与策略空间

| 决策 | 玩家需要判断 | 预期策略价值 |
|---|---|---|
| 唯一一杆 | 初始力量、角度、击散方向 | 决定第一批目标球状态与白球初始历史 |
| 何时开始回溯 | 目标球是否已进入历史路径，球桌是否形成新的碰撞机会 | 利用过去路线与现在布局的差异 |
| 回溯到哪里 | 历史中的哪个位置、速度方向适合重新进入物理 | 改变下一次主动运动的起点 |
| 何时松手 | 白球从哪一个历史片段分支出新的运动 | 产生不同的反弹、碰撞与进袋 |
| 是否利用库边 | 让白球获得更高速度，或避免高速失控 | 在有限初始击球条件下持续产生可操作的运动 |

**核心乐趣假设：** 玩家会从“想办法把球打进袋”，逐渐转为“设计白球的运动历史，让同一段轨迹在不同的球桌状态下产生新结果”。

必须通过实玩验证这一假设。系统交互复杂，不自动等于有趣；玩家需要看得懂轨迹、能控制结果、能从失败中学会下一次操作。

## 7. 画面与反馈（只做必要部分）

### 必须有

- 白球可识别的选中光圈和瞄准线、击球力度反馈。
- 白球历史轨迹的可见开关；正在回溯时以橙色区分。
- 正在回溯、第一杆已使用、胜利状态的明确提示。
- 目标球进袋计数（0/10 至 10/10）。
- 撞球、撞库、进袋、逆时碰撞的基础反馈；不影响物理结算。

### 可以有，但不作为 8h 原型的前提

- 轨迹随历史时间渐变、重复路径的时间层次展示。
- 撞库 ×1.5 的短暂脉冲或音效。
- 简单的清台时间、倒流次数结算。

不为反馈单独增加改变玩法结果的系统。

## 8. 原型范围与制作优先级

### P0：机制必须完整

1. 唯一一次瞄准击球；第二杆被禁止。
2. 正常台球碰撞、滚动衰减、库边、球袋。
3. 仅白球支持完整追加式历史与可重复回溯。
4. 回溯中对白球实施强制历史轨迹，对彩球保留单向碰撞影响。
5. 松开回溯后，白球携带逆向速度继续正常模拟。
6. 白球撞库动量 ×1.5、彩球维持普通反弹。
7. 目标球永久进袋、白球可救回、全部目标进袋判胜。
8. 暂停、重新开始、必要提示。

### P1：有时间再做

- 增强历史轨迹可读性，尤其是同一路径被多次经过的情况。
- 增强进袋、逆时碰撞、撞库反馈。
- 简单胜利数据（例如倒流次数）。

### 明确不做

时间传染、多人对战、AI 对手、技能树、时间能量条、标准八球规则、剧情、多关卡、复杂球杆系统、全世界时间回溯。

## 9. 验收测试

| 编号 | 操作 | 预期结果 |
|---|---|---|
| T01 | 首次拖动白球击出，再次尝试拖动 | 第一杆正常；第二杆不产生新冲量 |
| T02 | 白球 A→B，从 B 倒退到 C 后松开 | 在 C 的速度与原正向经过 C 时方向相反 |
| T03 | 白球随后 C→D，再按住回溯 | 按 D→C→B→A 顺序回放，旧历史未被删除 |
| T04 | 回溯白球撞击彩球 | 白球不偏离历史，彩球被推动并继续正常运动 |
| T05 | 彩球进袋后让白球多次倒流 | 彩球仍永久进袋，计数不减少 |
| T06 | 白球进入袋口后按 R | 白球可以沿自己的历史返回球桌 |
| T07 | 白球正常垂直撞库 | 反射后速度大小约为碰撞前 1.5 倍 |
| T08 | 白球正常斜向撞库 | 反射方向正确，速度向量整体乘以 1.5 |
| T09 | 白球倒流经过曾经的撞库点 | 不重复获得新的撞库增益 |
| T10 | 目标球全部进袋 | 显示清台，重新开局可恢复初始状态 |
| T11 | 轨迹很长、反复回溯、多次高速撞库 | 无明显卡顿、位置失真、碰撞穿透或脚本错误 |

## 10. 当前已知风险与待验证问题

1. **策略是否收敛：** 玩家会不会找到一种无脑重复倒流的方法，使进袋不再需要判断？
2. **残局可达性：** 只剩远离历史轨迹的目标球时，是否还有能力通过释放和撞库重新接近？
3. **速度失控：** ×1.5 撞库会不会引发指数式加速、穿球、失去操作空间？
4. **轨迹可读性：** 同一区域反复经过后，历史曲线是否变得难以理解？是否需要展示正在读取的历史时间段？
5. **回溯物理手感：** 白球不可阻挡但能推开其他球，是否符合玩家对“逆时”的直觉？是否需要更强表现解释？
6. **历史内存：** 完整历史会随实际运动次数增加；原型阶段保留完整路径，正式版本需测量存储成本，不能擅自牺牲规则一致性。

这些均为**待测试问题**，不是已经发生或必须通过增加机制解决的问题。

## 11. 当前可玩原型


当前代码已实现 P0 主要规则，并通过脚本级输入、ABCD 追加式历史、重复回溯、第二杆锁定与白球撞库增益测试。真实浏览器操作手感及完整清台可行性仍需试玩验证。

---

**设计原则：先验证一杆、回溯、碰撞这三者能否形成足够深的策略空间。如无必要，不增加新的时间能力或实体。**
