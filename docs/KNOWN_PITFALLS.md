# 已知陷阱与误判记录（Lead 维护）

> 目的：把**已经付出过代价**的错误记下来，避免重复。每条都注明「症状 → 根因 → 如何避免」。
> 本文件只记录**已发生并有证据**的事，不写猜测。

---

## T1｜Godot 写入静默失败（Low 完整性）

**症状**：脚本「成功」但什么都没发生。`DirAccess.make_dir_recursive_absolute()` **返回 `err=0 (OK)` 却不创建目录**；
`FileAccess.open(..., WRITE)` 失败（`err=12`）；`.godot/` 永远不出现；导入与运行静默失效，**不崩溃、不报错**。

**根因**：`D:\saint_ruin\tools\godot\` 下的可执行文件在本会话中运行于
**Low Mandatory Integrity Level**，对 Medium-IL 路径的写入被 Windows 强制完整性控制静默拒绝。
ACL 里**看不到**这个问题（`icacls` 不显示 `Mandatory Label` 项），只能靠**行为对照**发现。

**避免**：
- 一切脚本化 Godot 调用用 `D:\codename\codename_billiards\tools\godot\godot_console.exe`（工作区副本，IL 正常）。
- **禁止** PATH 上的裸 `godot`。
- **任何写操作后必须回读校验**，不得只信返回码。

## T2｜`godot.exe` 是 GUI 子系统程序，退出码不可信

**症状**：PowerShell 不等待进程结束，`$LASTEXITCODE` 不设置，CI 门禁形同虚设。

**根因**：`godot.exe` 是 PE subsystem 2（GUI）；`godot_console.exe` 是 subsystem 3（console）。

**避免**：脚本/CI 一律用 `godot_console.exe`。

---

## T3｜缺 `.sln` 时导出**静默丢掉 C# 程序集**

**症状**：导出返回 `rc=0`，写出 103 MB 的可执行文件，**但里面没有 C# 程序集**——只在运行时才炸。

**根因**：Godot 在无头模式下**不会**生成 `.csproj` / `.sln`（`--build-solutions` 会无限等待交互式提示）。

**避免**：`.csproj` 与 `.sln` 手工维护并**提交入库**；删除它们等于埋雷。

---

## T4｜Vulkan 在本机不可用，且**静默回退**

**症状**：渲染结果与预期不符，但没有任何报错。

**根因**：本机 Vulkan 初始化失败（`VkResult -3`），引擎静默回退到 D3D12。

**避免**：脚本化截图**必须显式传** `--rendering-driver d3d12`。

---

## T5｜`physics_jitter_fix` 默认值摧毁确定性

**症状**：同一关卡、同一输入，两次运行结果不同。无头测试与可解性求解器的地基被破坏。

**根因**：`physics/common/physics_jitter_fix` **默认 0.5**，会对 delta 做时间平滑。

**避免**：必须设为 **0**。

## T6｜陈旧构建产物导致的「幽灵报错」（Lead 实际踩过）

**症状**：日志里的异常指向 `LevelData.cs:line 291`，但**磁盘上的文件该处不是那个函数**
（`Validate()` 实际从 313 行开始，"no balls" 抛在 318 行）。
据此得出的结论是「有人改了 schema 破坏了 T07」——**完全错误**。

**根因**：报错来自**陈旧程序集**，或**与其他写入者交错的一次构建**。
Godot 的 `.godot/mono/temp/` 里存在多套构建产物（Debug / ExportRelease），
并发编辑时读取到旧产物是可能的。

**代价**：Lead 据此发了一封**错误指责队友**的消息，队友用原始输出反驳才纠正。
这是本会话最值得记住的一次协调失误。

**避免**：
1. **报错的 文件:行号 必须与磁盘上的文件对得上**。对不上就是陈旧产物，先重建再相信。
2. 下结论前先看 `git status`——本例中 `git status` 会立刻排除「改了 schema」这个假设。
3. **任何实验性门禁必须包含「负向对照」**（故意失败必须能失败），否则无法区分「门禁绿」与「门禁在骗人」。

## T7｜把「验证通过」当成「可玩」（产品层面的自我欺骗）

**症状**：内核 239/239 断言通过、机制已被求解器证明可解，
于是文档里出现「原型进展良好」这类表述——**而实际上没有任何人见过这个游戏**。

**根因**：把**可验证性**当成了**可玩性**。二者在这类项目里几乎不相关。

**避免**：`STATUS.md` 必须显式写明「**没有可玩版本**」，
并在拿到截图/试玩证据之前**不得**使用「可玩」「进展良好」一类措辞。
本项目的转折点正是 M2 产出第一批截图那一刻——在此之前，一切「完成」都只是无头数字。

## T8｜设计结论必须能被证伪，否则会污染后续所有工作

**症状**：求解器给出「6/6 关卡可解、±8° 容差」，被写进策划案当作事实。
对抗性验证推翻了其中 **3 条**（15.3% 走廊稀缺、0.153³ 论证、±8° 可瞄准），
其中「±8° 可瞄准」若未被推翻，会**直接误导关卡设计**——而真实窗口只有 **0.15°**。

**根因**：求解器与关卡生成器**共用同一套假设**，因此它能证明的只是**自洽性**，不是**可玩性**。

**避免**：
1. 关键结论必须由**独立实现**复现（本项目 `tools/verify_solver/` 就是这么做的）。
2. **容差必须是可测量的验收指标**，不是描述性形容词。
3. 报告必须**分开**列「未能证伪」与「未能成立」，且**撤回要写进文档**，不能悄悄删掉。
